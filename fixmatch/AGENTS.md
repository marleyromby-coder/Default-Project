This is FixMatch, an Expo/React Native iPhone app (Danish and English UI) for finding and comparing craftsmen and mechanics in Denmark, Sweden, Norway, Germany and the UK (Europe first, London as the first UK city) by price, distance and Trustpilot score. Prioritize mobile-first patterns, performance, and cross-platform compatibility. The web build is used as a demo and must keep working.

## FixMatch specifics

- All user-facing text goes through `src/i18n`: the Danish text is the key (`t('Danish text', params)`), and `src/i18n/en.ts` holds the English. Use `msg()` for texts stored in constants and translated later with `t(value)`, and `pick({ da, en })` for data. `src/__tests__/i18n.test.ts` fails if an English translation is missing.
- Prices are only compared within one country and shown in its currency (`src/lib/markets.ts`). Use `taxNote(market)` instead of hard-coding "inkl. moms", and format numbers, dates, prices and distances (km or miles) with `src/lib/format.ts`.
- A market only counts as open when it has businesses (`openCountries` in `src/lib/business-text.ts`). Launch guide: `docs/lancering/global-lancering.md`.
- Data modes: `EXPO_PUBLIC_FIXMATCH_DATA=demo|live`, `EXPO_PUBLIC_FIXMATCH_TRUSTPILOT=on|off` (see `src/lib/data-source.ts`, `src/lib/features.ts`). Trustpilot is off unless a build sets `on`; the Jest setup turns it on so the tests cover the full model. Never let demo data reach a production build.
- Ranking lives in `src/lib/ranking.ts`. Paid promotion must never affect scores, and any formula change must be reflected on the "Sådan rangerer vi" page in `src/data/content.ts` and `src/data/content-en.ts` (Danish Marketing Practices Act § 6 a, EU Omnibus Directive).
- Demo businesses are generated by `scripts/generate-demo-data.js`; real ones come from `npm run import:businesses` and require a consent date.
- Anything that mentions reviews or Trustpilot must be hidden when `TRUSTPILOT_ENABLED` is false (`src/lib/features.ts`), including accessibility labels and the info pages. `src/__tests__/trustpilot-off.test.ts` covers the shared texts.
- `scripts/check-release.js` (`npm run check:release`, and `eas-build-pre-install` on EAS) blocks live builds without consented businesses or with TODOs in `src/constants/app-info.ts`.
- The public website (`npm run website:build` → `dist-website/`) is built from `docs/jura/*.md` and `website/*.md`. Keep the Danish and English legal texts in step, use `{{publisher}}`, `{{email}}` and `{{updated}}` instead of hard-coded details, and start notes for the team with `>`.
- Widgets live in `src/widgets/` (expo-widgets + `@expo/ui/swift-ui`). A function with the `'widget'` directive is serialised and runs in the widget extension: it may only use its props, the environment and SwiftUI components/modifiers – no closures over module constants, no `@/` imports, no `t()`. Translate and format in `src/widgets/props.ts`. Run `npm run widgets:check` after changing a widget.
- Design: take colours from `useTheme()` (`src/constants/theme.ts`) – never hard-code them – and keep every text pair at 4.5:1 or more. `accent` (ochre) is decoration only, never text. Titles are set in Fraunces by `AppText`; the root layout loads the two weights in `SerifFonts`, and each weight is its own family, so never add `fontWeight` to serif text. The logo outline lives in `assets/brand/mark.json`; after changing it, run `npm run brand:render`.
- Light/dark: always use `useTheme()`/`useIsDark()` from `src/hooks/use-theme.ts`, never React Native's `useColorScheme`, so the user's choice under Mere → Udseende (`src/state/appearance.ts`) applies.
- Layout by width, never by orientation (the iPhone Duo's inner display ignores orientation locks): `useLayout()` in `src/hooks/use-layout.ts` gives `column` for scroll content, `gutter` for full-width bars and `wide` for side-by-side layouts.
- `plugins/with-fixmatch-widgets.js` adds the logo images and iOS 27's `systemExtraLargePortrait` to the widget extension. It must stay listed before `expo-widgets` in `app.json`.
- `npm run ios:xcode` (`scripts/open-xcode.js`) is the way to get an Xcode project: it refuses to run while Xcode is open, runs prebuild and `pod install`, clears FixMatch's DerivedData and Xcode's module cache and opens the `.xcworkspace`. `plugins/with-implicit-modules.js` turns off Xcode's explicitly built modules (`SWIFT_ENABLE_EXPLICIT_MODULES`/`CLANG_ENABLE_EXPLICIT_MODULES = NO`), which fail with CocoaPods on stale caches, and `plugins/with-quiet-xcode.js` silences the warnings of generated and third-party native code (pods, Expo's configure script, prebuilt React/Expo headers, Hermes), so Xcode shows 0 warnings and a new one stands out. CI prints every warning in its "Count errors and warnings" step. `.github/workflows/fixmatch-ios.yml` builds the app with Xcode 27.1 and 26.6 (Debug for the simulator and an iPhone, and an unsigned Archive) on every push; check it after native changes.
- Accounts (`src/state/account.ts`) and business sign-ups (`src/lib/business-signup.ts`) use Supabase (`src/lib/supabase.ts`, EU). Without `EXPO_PUBLIC_SUPABASE_URL`/`_KEY` everything must keep working locally. Anything that contacts a business must go through `requireContactProfile()` and `logContact()`. Schema changes go in a new file in `supabase/migrations/` with row level security, and `docs/lancering/supabase.md`, the privacy policies (docs/jura and `src/data/content*.ts`), the App Store privacy answers and `ios.privacyManifests` in `app.json` must match what is collected.
- Changing the consent statements means bumping `CONSENT_VERSION`. The website form (`scripts/lib/signup-form.js`) reads the statements from the app's source, so both stay identical.
- Run `npm run check` (tsc, eslint, jest) before declaring a task done.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Commands

Use `bunx` instead of `npx` if the project uses bun (`bun.lock` present).

```bash
npx expo install <package>  # ALWAYS use instead of npm/yarn/pnpm/bun add — resolves SDK-compatible versions
npx expo start              # start the dev server
npx expo lint               # lint
npx tsc --noEmit            # typecheck
npx expo-doctor             # diagnose dependency and config issues
npx expo install --fix      # fix incompatible package versions
```

Run lint and typecheck before declaring any task done.

## Navigation & Routing

- Use **Expo Router** for all navigation. Routes live in `src/app/` — every file there is a screen, `_layout.tsx` files define navigators. Keep non-route code (components, hooks, utils) outside `src/app/`.
- Import `Link`, `router`, and `useLocalSearchParams` from `expo-router`.
- Docs: https://docs.expo.dev/router/introduction.md

## Building with EAS

Use EAS to build, sign, and submit the app in the cloud (`eas build`, `eas submit`) and to ship over-the-air updates (`eas update`) — no local Xcode or Android Studio required. Run EAS CLI as `bunx eas-cli <command>` in Bun projects, or `npx eas-cli@latest <command>` otherwise; substitute that for bare `eas` in docs examples.
Docs: https://docs.expo.dev/eas/index.md

## Rules

- If `ios/` and `android/` directories do not exist, they are generated (Continuous Native Generation). Never create or edit them by hand — configure native behavior in `app.json` and config plugins.
- Expo Go only includes its bundled native modules. After adding a library with native code, the app needs a development build: `npx expo run:ios|android` locally, or `eas build --profile development`.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md
